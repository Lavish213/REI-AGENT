## Defects found and fixed during this run

1. **ARV was being discarded.** `economics()` returned only nulls whenever any of
   ARV, repairs or asking price was missing. Since repairs are usually absent at
   brief time, most of the dashboard would have shown an em dash for ARVs Bob had
   actually computed. Known inputs are now always reported; only the derived
   purchase limit and headroom need all three.
2. **Grading could crash a brief.** Fuzzing found two inputs that raised inside
   `generate_call_brief`, which would have destroyed the brief and the call over an
   advisory number. A string of blocked reasons was also being split into
   characters. 20,000 randomized hostile inputs now raise zero exceptions, and a
   grading failure can no longer take the brief down with it.
3. **No index on `bob_decisions`.** The overview's latest-per-lead scan was a
   sequential scan plus sort over a table that grows every brief refresh. Indexed,
   and `EXPLAIN` confirms the index is usable for that exact query shape.
4. **A 5-second proxy timeout** on a query heavier than the one beside it. Raised
   to 10.
5. **Global `Decimal` precision leak.** My own new finance tests set
   `getcontext().prec` at module import, which changed valuation rounding for every
   later test. The drift gate caught it; a guard test now prevents the class.
6. **Three layout defects** in the panel, found by rendering the real component:
   colliding columns, "of ARV" trailing an em dash with no figure, and "1 comps".

On (5) I pushed the offending commit before reading the test output, because a
piped `pytest` hid the failure behind a zero exit code. The fix is in the next
commit.

- **Section 12 financing mathematics**: loan to value and cost, debt yield, yield
  on cost, interest-only with balloon, points and fees, remaining balance,

  closed-form balance matches a 120-iteration amortization loop exactly.

## Honest limits

- **The finance functions have no caller yet.** They are library code. Section 12
  coverage improved; nothing in the grading path uses LTV or IRR, because Bob does
  not hold loan terms.

  on the `offers` table, not `properties`, so Bob usually cannot see them at brief
  time. I deliberately did not wire `offers.repair_estimate` in, because its
  default is a flat $25,000 buffer and treating that as a measured estimate is the
  exact error the grading is built to avoid.
