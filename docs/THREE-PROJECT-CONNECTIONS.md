# Three-project connection diagnostics

Canonical chain: Bob-Intelligence- worker ↔ shared tenant-bound Supabase ↔ REI-AGENT Sophia ↔ The-Dashboard API/frontend. Configure KARPATHYS_URL, KARPATHYS_WEBHOOK_SECRET and the private durable KARPATHYS_OUTBOX_PATH for source→dashboard delivery. Configure the same SOURCE_COMMAND_SECRET on Sophia and the dashboard's REI_COMMAND_URL gateway for reverse commands. Keep the Bob/Sophia tenant equal to the dashboard REI_SOURCE_TENANT_ID. The dashboard database is separate from the shared source database.

GET /api/operations/integration?challenge=UUID requires the source-command service secret. It reports the shared Bob/schema/worker and fact-journal status, local dashboard delivery journal, and an authenticated callback to /api/v1/ingest/connection. Schema, UUID challenge and tenant must match. The returned dashboard receiver identity lets the requesting dashboard detect a different configured database endpoint. No provider calls, bookings, permissions or quotes are created by this diagnostic. Outbound and background-job configuration remain separate reported flags.

The dashboard's source review page displays all these edges. Its offline backend/scripts/verify_project_wiring.py compares private Bob/Sophia/dashboard config exports without printing values. The full transport/topology, browser origin, storage and acceptance contract is The-Dashboard/docs/THREE-PROJECT-CONNECTIONS.md. Configuration consistency and loopback test results are not live connectivity, persistence-volume or provider-delivery proof. No new database migration is required for the diagnostics themselves; existing reviewed application migrations are still required.
