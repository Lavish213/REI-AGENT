# Workflow recovery and operational synchronization

Implemented and locally tested: durable five-touch schedules; atomic claim ownership; permanent quarantine of uncertain processing outcomes; no cooldown bypass; tenant-bound inbound email threads and immutable event replays; durable intake before remote application; duplicate-safe PostgreSQL reply application; email pause after replies; explicit suppression on STOP; source snapshot callbacks, follow-ups, offers and email replies; version-bound source callback commands with persistence receipts.

The new email endpoint is a normalized authenticated adapter contract, not a claim that SendGrid sends custom HMAC headers. A trusted receiving adapter must verify transport and sender authentication, reject unauthenticated sender assertions, extract the reply token, and submit only bounded normalized JSON. INBOUND_EMAIL_ADAPTER_SECRET must contain at least 32 characters. Headers are X-Email-Timestamp and X-Email-Signature; signature is HMAC-SHA256(timestamp + '.' + exact raw JSON body). Fields: event_id, thread_token, sender, sender_verified=true, text. Receiving domains/MX and the provider adapter need live account configuration. Official reference: https://www.twilio.com/docs/sendgrid/for-developers/parsing-email/setting-up-the-inbound-parse-webhook . Outgoing lead emails use a persisted random reply token when INBOUND_EMAIL_DOMAIN is set. Unbound emails do not acquire guessed lead identity.

Dashboard source command transport uses REI_COMMAND_URL and SOURCE_COMMAND_SECRET; Sophia must use the same SOURCE_COMMAND_SECRET. Callback commands are role-checked in the dashboard, bound to tenant/lead/property and exact source updated_at, durably queued, and applied once by the source SQL function. A queued command is not a confirmed callback. Source data revisions and delivery receipts stay distinct. Stale versions and changed destinations require review. The source never automatically converts arbitrary dashboard edits into price authority.

Dashboard calendar/deals/follow-ups now display actual source records alongside existing dashboard records. They preserve walkthrough/callback/follow-up distinctions and label stale snapshots. Callback write-back is implemented; full arbitrary bidirectional changes to offers, disposition, booking cancellation and source candidates are not implemented by this patch.

WORKFLOW_JOURNAL_PATH must be an absolute private persistent path (default /data/sophia/workflows.sqlite3). Pending work survives restarts; stale processing claims are quarantined after ten minutes instead of redialed. The journal is SQLite: actual volume durability and replica topology require deployment acceptance. WORKFLOW_REVIEW_OWNER_ID must designate a real operator. Health and review queue endpoints expose job state and uncertain outcomes. Health does not prove a mounted persistent volume.

Externally blocked: production account/DNS/adapter setup; real audio/provider tests; current San Joaquin held-out sold/condition/repair evidence; actual shared database baseline and data-preserving upgrade/rollback; verified volume/replica behavior. County assessed values are not sale-price or ARV truth. Official county source: https://www.sjgov.org/department/assessor/property-information/homeowners . Do not grade current California valuation accuracy using tax assessments or synthetic comp invariants.

Source candidates now have a dashboard review page with authenticated source proxying, fingerprint-bound review decisions and no contact/offer grant. Exact source replays preserve the prior classification; changed evidence returns to review. Workflow health exposes an explicit missing-owner state and uncertain jobs can be annotated and skipped by an authenticated operator; they cannot be automatically resent. Source callback recovery queries cast legacy JSON metadata to JSONB and copy nested state before mutation, so confirmed receipts persist and completed commands leave the retry queue.

Verified email replies now pause local drip delivery directly from the durable inbound journal, before the remote reply RPC succeeds. Explicit STOP phrases also block the canonical lead's calls, SMS and bound email, and block the replying email address. The check reads retained intake events, so it survives a crash between intake and the separate address-suppression journal and remains active after remote recovery. Unavailable journal checks deny delivery. Ordinary replies pause email only. These holds are tenant-bound and are not cleared by an unrelated database edit or a non-STOP replay; an explicit reviewed resumption workflow is not implemented. SQLite journal durability and multi-replica visibility still require deployment verification.

Source pricing review now has a dedicated dashboard queue. The gateway requires the existing approvals:resolve permission (admin/reviewer), derives the actor from authentication, validates integer-cent whole-dollar bounds and requires a reason. The source binds the viewed fingerprint to the property, lead, call, action, expiry and request context. ## Reviewed email resumption

The earlier resumption gap is now implemented for ordinary replies. The source review page shows reply holds, receipt state and explicit STOP restrictions. Authenticated admin/operators may review an existing email sequence with a reason and a current evidence fingerprint. This never clears STOP, DNC, opt-out, completed-campaign or address-suppression state, creates contact permission, resets email cadence/progress, or starts a missing campaign.

Apply 20261019_reviewed_email_resume.sql after 20261018_source_operations.sql. The source locks the lead, checks the exact sorted reply-ID set and canonical owner email, requires an existing non-completed campaign and records an atomic source receipt. SQLite records the operator intent before the RPC and advances the local reply cutoff only after a matching receipt and a second evidence check. New ordinary replies and STOP replies arriving during recovery leave the hold active and require fresh review. Identical retries retain the request identity; pending reviewed intents recover on the 30-second workflow sweep with a bounded retry budget. STOP history remains immutable for enforcement. Explicitly reviewed resumption permits ordinary email follow-ups only; it does not resend an uncertain outbound message.

CONTACT_SUPPRESSION_PATH, COMMUNICATION_JOURNAL_PATH and WORKFLOW_JOURNAL_PATH must all be private durable paths. Bound lead email now checks the durable phone STOP journal as well as email holds, so a database outage cannot turn a locally recorded phone STOP into permission to email that lead. Missing suppression state denies contact. Multi-replica shared-state visibility, actual volume recovery and live provider behavior remain deployment acceptance requirements; private SQLite journals are not a distributed consistency claim. More than 500 reply events for one lead require manual archival/evidence review rather than an unbounded resumption payload.
